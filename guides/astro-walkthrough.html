chaivoot design system / walkthrough

Walkthrough · 12 min read

Astro คืออะไร — และทำไมเหมาะกับ chaivoot.com

เอกสารฉบับนี้พา walk-through ทุกแนวคิดที่ต้องเข้าใจก่อนจะให้ Claude Code ลงมือ scaffold โปรเจกต์จริง อ่านจบจะรู้ว่าโครงสร้างหน้าตาเป็นยังไง, การเขียน post ทำอะไรบ้าง, และ deploy เป็น chaivoot.com ขึ้น Vercel ได้ยังไง — ทั้งหมดนี้เลี่ยง command line ได้เกือบ 100% หลัง setup

สารบัญ
  1. ทำไมต้อง Astro (ไม่ใช่ Next.js / WordPress)
  2. โมเดลความคิด: HTML-first, Islands
  3. โครงสร้าง folder ของจริง
  4. .astro file ทำงานยังไง
  5. Content Collections — หัวใจของ blog
  6. เขียน post 1 อัน — ตั้งแต่ต้นจนจบ
  7. Publish workflow (ไม่แตะ command line)
  8. Deploy ขึ้น Vercel
  9. ขั้นต่อไป — ส่งให้ Claude Code

01ทำไมต้อง Astro

คุณเคยลอง Next.js มาแล้วในโปรเจกต์ dogevityfood.com และคงรู้สึกว่ามันทำได้ทุกอย่าง — แต่ก็ overhead เยอะ. Astro ออกแบบมาเพื่อ "เว็บที่ content เป็นพระเอก" — blog, docs, marketing site, digital garden. ทุกอย่างที่ Next.js ทำได้แต่หนักเกิน, Astro ทำเบาๆ

สำหรับ chaivoot ซึ่งจะเป็น บันทึก + บทความ ที่ไม่มี login, ไม่มี cart, ไม่มี realtime — Astro เลือกง่ายมาก

เทียบ WordPress สั้นๆ

WordPress ต้องมี database (MySQL), ต้อง host แบบ dynamic, ต้อง update ตลอดเพราะ security. Astro ไม่มี database — post คือไฟล์ .md ใน Git. ปลอดภัยกว่า, เร็วกว่า, ฟรี hosting, แต่แลกกับการเขียน post ผ่าน editor แทน admin panel

02โมเดลความคิด — HTML-first, Islands

ต่างจาก Next.js ที่ "เริ่มจาก React component แล้วค่อย render เป็น HTML" — Astro เริ่มจาก HTML แล้วค่อยเติม JS เฉพาะจุดที่ต้องการ. แต่ละจุด interactive เรียกว่า Island

analogy

นึกภาพเว็บเป็น หน้ากระดาษ. Next.js คือกระดาษทั้งหน้าเป็น "app" — ต้อง boot React ขึ้นมา hydrate ทุกอย่าง. Astro คือกระดาษ static + มี "เกาะ" interactive เล็กๆ ลอยอยู่บนกระดาษ — เกาะไหนต้องการ JS ก็ ship JS แค่เกาะนั้น เกาะที่เหลือเป็น HTML pure

ผลลัพธ์: หน้า blog 1 หน้า (text ล้วน + รูป) → ส่ง 0 KB JavaScript. ถ้ามี search box ที่ติด React → ส่ง JS เฉพาะของ search box. ถ้ามี comment section → ส่ง JS เฉพาะ comment

สิ่งที่ chaivoot จะใช้ (และไม่ใช้)

  • ใช้: Astro pages (.astro), Markdown สำหรับ post, CSS ของเรา (port จาก colors_and_type.css), Vercel deploy
  • ไม่ใช้ตอนเริ่มต้น: React, Vue, Svelte, Tailwind, MDX, image optimization plugins. เริ่มเรียบๆ ก่อน เพิ่มทีหลังได้ทุกเมื่อ

03โครงสร้าง folder

นี่คือ folder ที่ Claude Code จะ generate ให้คุณ. โครงสร้างนี้ ทุกอย่างที่คุณเห็นจะอยู่ใน GitHub และ Vercel จะอ่านจาก GitHub เพื่อ build site

chaivoot.com/ ├── src/ │ ├── pages/ ← แต่ละไฟล์ = 1 หน้าของเว็บ │ │ ├── index.astro → chaivoot.com/ │ │ ├── about.astro → chaivoot.com/about │ │ ├── pillars/ │ │ │ ├── amway.astro → /pillars/amway │ │ │ ├── longevity.astro → /pillars/longevity │ │ │ └── dogs.astro → /pillars/dogs │ │ └── blog/ │ │ └── [slug].astro ← template สำหรับ post ทุกอัน │ │ │ ├── content/ ← post ทั้งหมดอยู่ที่นี่ │ │ ├── config.ts ← schema ของ post │ │ └── blog/ │ │ ├── 2026-02-05-barf-diet.md │ │ ├── 2026-02-12-amway-12-week.md │ │ └── ... │ │ │ ├── layouts/ ← shell + nav + footer │ │ ├── BaseLayout.astro │ │ └── PostLayout.astro │ │ │ ├── components/ ← ชิ้นส่วน reuse │ │ ├── Nav.astro │ │ ├── PillarBadge.astro │ │ └── PostCard.astro │ │ │ └── styles/ │ └── tokens.css ← ของจาก design system │ ├── public/ ← ไฟล์ static (รูป, favicon) │ ├── favicon.svg │ └── photos/ │ └── chaivoot-portrait.jpg │ ├── package.json ← dependencies ├── astro.config.mjs ← Astro settings └── README.md

สิ่งที่คุณจะแตะบ่อย มี 1 folder:

  • src/content/blog/ — เพิ่ม .md ใหม่ = post ใหม่. นี่คือ 90% ของงาน

ส่วน folder อื่นๆ เป็น โครงเว็บ ที่ตั้งครั้งเดียวจบ — แตะแค่ตอนปรับ design

04.astro file ทำงานยังไง

ไฟล์ .astro มี 2 ส่วน คั่นด้วย ---:

  • ด้านบน (frontmatter): JS / TS — ดึงข้อมูล, import component, prepare ตัวแปร
  • ด้านล่าง: HTML + เสียบตัวแปรด้วย {...}

ลองดูตัวอย่างหน้า home ของ chaivoot:

src/pages/index.astro
--- // ส่วนนี้ run ตอน build เท่านั้น — ไม่ส่งไป browser import { getCollection } from 'astro:content'; import BaseLayout from '../layouts/BaseLayout.astro'; import PostCard from '../components/PostCard.astro'; const posts = await getCollection('blog'); const recent = posts .sort((a, b) => b.data.date - a.data.date) .slice(0, 12); --- <BaseLayout title="chaivoot — บันทึก"> <section class="hero"> <h1>บันทึกของชายวัย 50 กับหมา 1 ตัว</h1> <p>ที่สนใจ Longevity และธุรกิจ Amway</p> </section> <section class="feed"> {recent.map((post) => ( <PostCard post={post} /> ))} </section> </BaseLayout>

สังเกต 3 อย่าง:

  1. Frontmatter (ระหว่าง ---) เขียน JavaScript ได้ตามใจ. await ก็ได้ — เพราะ run ตอน build เท่านั้น
  2. HTML เขียนเหมือน HTML ปกติ. <BaseLayout> และ <PostCard> คือ component (เริ่มต้นด้วยตัวพิมพ์ใหญ่)
  3. {...} เสียบ JS expression. JSX ผู้ใช้ React จะคุ้น — เกือบเหมือนกัน

นั่นคือทั้งภาษา. ไม่มี hooks, ไม่มี state, ไม่มี client/server boundary. มันแค่ template engine ที่เขียน JS ในส่วน data-prep ได้

05Content Collections — หัวใจของ blog

นี่คือ feature ที่ทำให้ Astro โดดเด่นเหนือ Next.js สำหรับ blog. Content Collection คือ folder ของไฟล์ .md ที่ Astro รู้จักและ index ให้อัตโนมัติ พร้อม type-check schema ของแต่ละ post

ขั้นตอน 1 — กำหนด schema

บอก Astro ว่า post แต่ละอันต้องมี field อะไรบ้าง:

src/content/config.ts
import { defineCollection, z } from 'astro:content'; const blog = defineCollection({ type: 'content', schema: z.object({ title: z.string(), date: z.date(), pillar: z.enum(['amway', 'longevity', 'dogs']), format: z.enum(['note', 'article']), excerpt: z.string().optional(), draft: z.boolean().default(false), }), }); export const collections = { blog };

นี่คือ contract — Astro จะร้องเอ็ดถ้าคุณเขียน post ขาด field. มันคือ guard rail ที่ป้องกันคุณ ship post พังโดยไม่รู้ตัว

ขั้นตอน 2 — เขียน post

สร้างไฟล์ใน src/content/blog/:

src/content/blog/2026-02-05-barf-diet.md
--- title: "โภชนาการหมา: ทำไมผมเลือก BARF" date: 2026-02-05 pillar: dogs format: article excerpt: "หลังจาก 6 เดือนที่ทดลอง raw food, นี่คือสิ่งที่เปลี่ยน" --- ตอนแรกผมก็ลังเล — มันดูยุ่งยาก แพง และต้องเก็บในตู้เย็น แต่หลัง 6 เดือนที่ทดลอง, มอมแมมมีอะไรเปลี่ยน: - ขนเงา ไม่มัน - น้ำหนักลง 800g - พลังงานสม่ำเสมอตลอดวัน ## สูตรที่ผมใช้ 70% เนื้อ, 10% กระดูก, 10% เครื่องใน, 10% ผัก ...

คุณเขียน markdown ปกติ ที่ใครก็เขียนเป็น (ใน Obsidian, VS Code, หรือ GitHub web editor). Astro รับ heading, list, link, image, code block ทั้งหมด

ขั้นตอน 3 — แสดงในหน้าเว็บ

หน้า [slug].astro ทำหน้าที่ render ทุก post เป็นหน้าเดี่ยว. คุณเขียนครั้งเดียว, ใช้กับ post ทุกอันในอนาคต:

src/pages/blog/[slug].astro
--- import { getCollection } from 'astro:content'; import PostLayout from '../../layouts/PostLayout.astro'; // บอก Astro ว่ามี post อะไรบ้าง — มันจะ build แต่ละ post เป็น HTML ของตัวเอง export async function getStaticPaths() { const posts = await getCollection('blog'); return posts.map((post) => ({ params: { slug: post.slug }, props: { post }, })); } const { post } = Astro.props; const { Content } = await post.render(); --- <PostLayout post={post}> <Content /> {/* ← markdown ที่ render เป็น HTML แล้ว */} </PostLayout>

เพิ่ม post ใหม่ → Astro detect .md ใหม่ → build หน้าใหม่ที่ chaivoot.com/blog/[slug] ให้อัตโนมัติ. คุณไม่ต้องแก้ไฟล์ [slug].astro อีกเลย

06เขียน post 1 อัน — ตั้งแต่ต้นจนจบ

สมมติคุณนั่งอยู่หน้าจอตอนนี้ อยากเขียน note เรื่องที่เพิ่งคิดได้. ลำดับเหตุการณ์มีแค่นี้:

1. เปิด Obsidian (หรือ VS Code, หรือ github.com ใน browser)
เปิด folder chaivoot.com/src/content/blog/
2. สร้างไฟล์ใหม่ — ตั้งชื่อตามวันที่
2026-02-15-line-vs-blog.md
3. กรอก frontmatter (5 บรรทัดบนสุด)
title, date, pillar, format, excerpt
4. เขียนเนื้อหา — markdown ปกติ
heading, paragraph, list, link, รูป (ใส่ ![alt](/photos/foo.jpg) ก็ใช้ได้)
5. Save
ถ้าใช้ Obsidian + Git plugin — sync auto. ถ้า GitHub web — กด "Commit"
6. รอ 1–2 นาที
Vercel detect commit → build → live ที่ chaivoot.com

ไม่มี npm run. ไม่มี admin login. ไม่มี database backup. แค่ เขียน → save → push → live

07Publish workflow แบบเลี่ยง command line

นี่คือสิ่งที่คุณบอกว่าสำคัญที่สุด. ผมเสนอ 3 ทางเลือก เรียงจาก "ง่ายที่สุด" → "control เยอะที่สุด":

เปิด browser → github.com/chaivoot/chaivoot.com → src/content/blog → "Add file"

  • ไม่ต้อง install อะไร 0% — แค่มี browser
  • เขียน markdown ใน editor ของ GitHub โดยตรง
  • Preview tab โชว์ผลก่อน commit
  • กด "Commit" → 1 นาทีต่อมา live
  • เหมาะถ้า: เขียน post ไม่บ่อย, ไม่อยาก install อะไรในเครื่อง
ข้อเสีย

เขียน offline ไม่ได้, no version local, ถ้า internet หลุดเสีย draft ทิ้ง

Obsidian app + community plugin "Git"

  • เปิด chaivoot.com folder ใน Obsidian — มันเป็น vault
  • เขียน post ใน editor ที่คุ้นเคย พร้อม preview, link ระหว่าง note, etc.
  • Git plugin auto-pull ตอนเปิด, auto-commit ตอน save, auto-push ทุก N นาที
  • Save ใน Obsidian = push GitHub = deploy Vercel
  • เหมาะถ้า: เขียนบ่อย, ใช้ Obsidian อยู่แล้ว, อยากเขียน offline
ตั้งครั้งแรก

ต้องตั้ง Git plugin (3–5 นาที) — Claude Code ช่วยได้. หลังจากนั้นเขียน 100% เหมือน note ปกติ

GitHub Desktop (GUI app) + editor ที่ชอบ

  • Install GitHub Desktop — clone repo ลงเครื่อง
  • เขียนใน editor ใดก็ได้ (VS Code, Obsidian, even TextEdit)
  • เปิด GitHub Desktop → เห็น changes → กด "Commit" → กด "Push"
  • 3 ปุ่ม, ไม่มี command line
  • เหมาะถ้า: อยาก control commit message, review change ก่อน push

คำแนะนำของผม: เริ่ม ทาง 1 (GitHub web) ก่อน — 0 setup. ถ้าเริ่มเขียนบ่อยขึ้นค่อย upgrade เป็น Obsidian (ทาง 2)

08Deploy ขึ้น Vercel

Setup ครั้งเดียว — Claude Code ทำให้. หลังจากนั้น auto ตลอด:

01 · YOU เขียน .md ใน editor
02 · YOU Commit GitHub web / Desktop
03 · AUTO GitHub webhook notify Vercel
04 · AUTO Vercel build ~30 วินาที
↓
05 · AUTO Deploy CDN ทั่วโลก edge servers
06 · LIVE chaivoot.com post ใหม่ขึ้น

ส่วนที่คุณแตะ = สีน้ำตาล (2 step). ที่เหลือ Vercel ทำเอง

Preview deployment (โบนัส)

ทุก commit ที่ไม่ใช่ main branch — Vercel สร้าง preview URL ลับ ให้ดูก่อน. เช่น chaivoot-com-git-draft-amway-post.vercel.app. คุณเปิดดูจาก phone ก่อน merge → ค่อย publish จริง

09ขั้นต่อไป — ส่งให้ Claude Code

ถึงตรงนี้คุณรู้ภาพ Astro ทั้งหมดแล้ว. ขั้นต่อไปผมจะสร้าง scaffold blueprint + HANDOFF.md ในโปรเจกต์นี้ ที่ Claude Code อ่านแล้ว execute ต่อได้เลย

สิ่งที่ผมจะส่งให้ Claude Code:

  1. Scaffold blueprint folder — sample .astro, .md, config.ts ที่ port design system แล้ว. Claude Code copy เข้า Astro project ใหม่ได้เลย
  2. HANDOFF.md — checklist step-by-step:
    • Run npm create astro ใน sandbox
    • Copy blueprint files
    • Setup chaivoot/chaivoot.com repo ใน GitHub
    • Connect Vercel + custom domain
    • Verify หน้าเว็บโผล่ที่ chaivoot.com
  3. Token CSS — copy colors_and_type.css ไป src/styles/tokens.css ตรงๆ (zero conversion)

เมื่อ Claude Code setup เสร็จ คุณจะได้ chaivoot.com ที่ live จริง พร้อม sample post 2–3 อัน. แทนที่ post ตัวอย่างด้วย post ของคุณเอง → done

พร้อมต่อเลยมั้ย?

ผมสร้าง scaffold + handoff ให้ตอนนี้ได้เลย. หรือถ้ายังมีคำถามเรื่อง Astro อยากให้ขยายตรงไหนเพิ่ม บอกได้
